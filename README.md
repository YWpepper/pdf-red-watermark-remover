# pdffix — PDF 红色水印清除工具

批量清除 PDF 中的**红色水印**（页眉广告、斜向「严禁复制 打印 避免侵权」等），用于清洗
讲义 / 试卷 / 扫描件数据集。

采用**内容流手术法**：只删除 PDF 内容流中「以红色绘制」的那几条文字指令，
**图像字节、黑色正文、字体、元数据、页码结构一律不动**。

```
原始 PDF                                   处理后
┌──────────────────────────┐              ┌──────────────────────────┐
│  ▓▓ 扫描图（逐字节保留）   │              │  ▓▓ 扫描图（逐字节保留）   │
│      ← 黑色正文原样         │              │      ← 黑色正文原样         │
│  红色页眉水印  ← 删除       │              │                          │
│  红色斜向水印  ← 删除       │              │                          │
└──────────────────────────┘              └──────────────────────────┘
```

对 15 本讲义、3846 页实测：

| 检查项 | 结果 |
|---|---|
| 渲染后红色像素 | 抽样 135,743 → **0** |
| 图像对象字节 | **逐字节完全一致** ✓ |
| 黑色正文文本层 | **逐页完全一致**（差异页数 0） ✓ |
| 页数 / 目录 / 字体 | 不变 ✓ |
| 体积变化 | 基本不变 |

## 安装

需要 Python 3.8+。

```bash
git clone https://github.com/YWpepper/pdf-red-watermark-remover.git
cd pdf-red-watermark-remover
python3 -m pip install --user pymupdf        # 唯一依赖
```

也可以正式安装成命令：

```bash
python3 -m pip install --user -e .            # 装完后直接用 pdffix
```

## 三种使用方式

### 1. 图形界面（最省事）

```bash
python3 -m pdffix --gui
```

或在 macOS 上双击 [`scripts/pdffix.command`](scripts/pdffix.command)（首次运行会自动装依赖）。

界面里选择输入目录 → 选择输出目录 → 点「开始处理」，带实时进度与日志。

### 2. 命令行

```bash
# 处理目录内所有 PDF，输出到 <目录>_去水印
pdffix ~/讲义目录

# 指定输出目录 / 递归子目录 / 只看不改
pdffix ~/讲义目录 -o ~/干净讲义
pdffix ~/讲义目录 --recursive
pdffix ~/讲义目录 --survey          # 统计红色水印，不写文件
pdffix ~/讲义目录 --dry-run         # 只扫描统计
```

| 参数 | 说明 |
|---|---|
| `-o, --outdir` | 输出目录，默认 `<输入目录>_去水印` |
| `--recursive` | 递归处理子目录 |
| `--pattern` | 文件匹配，默认 `*.pdf` |
| `--in-place` | 原地覆盖原文件（**不推荐**） |
| `--survey` | 只统计红色水印与红色文本样本 |
| `--no-verify` | 跳过处理后的自动校验 |

### 3. 作为 Python 库

```python
from pdffix import remove_red_watermark

report = remove_red_watermark("in.pdf", "out.pdf")
print(report.ok, report.pages, report.cleaned_pages, report.red_chars_left)
```

## 内置自检

```bash
pdffix --selftest
```

会即时合成一份「黑字正文 + 红色页眉 + 红色斜向水印」的 PDF，跑一遍完整流程，
并断言：红字归零、黑字逐页不变、页数不变。不依赖任何外部文件，
用来快速确认安装是否正常。

## 工作原理

PDF 页面内容是一段「内容流」程序。文字用 show-text 指令（`Tj` / `TJ` / `'` / `"`）
绘制，绘制前用 `rg` / `g` / `k` 设置填色颜色。

pdffix 完整解析内容流的操作符序列，维护图形状态栈（`q` / `Q`）与当前填色，
**精确找出填色为红色的 show-text 指令并逐字节删除**。水印通常出现在两个位置：

| 位置 | 典型内容 | 处理方式 |
|---|---|---|
| **Form XObject** | 页眉广告（流内带 `/PieceInfo /Private /Watermark` 标记） | 原位改写该共享对象 |
| **页面内容流** | 斜向「严禁复制 打印 避免侵权」 | 原位改写页面内容流 |

### 为什么不直接用「矩形遮盖」？

最直觉的做法是把水印外接框涂白。但斜向水印的**轴对齐外接框很大**，
会连带删掉正文黑色文字 —— 实测某本讲义会误删约 6 万字符。
pdffix 只删指令本身，框多大都不影响正文。

### 为什么不栅格化？

`page.get_pixmap()` 重新渲染会把整页变成位图，损失可搜索文字层与矢量质量。
pdffix 改的是指令层，图像流一个字节都不动（已用 MD5 逐对象核对）。

### 内置安全校验

每个文件处理完逐页校验：

1. 红色字符数必须归零；
2. **非红色字符数必须与处理前完全一致**。

任一不符即丢弃该文件、不输出半成品。

## 适用范围与边界

**适合**：水印是「红色文字」叠加层（绝大多数电子讲义、网课导出的 PDF）。

**不处理**：

- 水印被**烧进扫描图片**里的（像素级红色）——需要额外的图像处理，本工具不动；
- 水印是**黑色/灰色**的；
- 书籍正文本身用红色印刷的图示——那属于正文内容，会被保留。

自检与实测都基于「红色叠加文字」这一形态。如果你的 PDF 水印形态不同，
先用 `--survey` 看看红色字符数是否为 0，再决定是否适用。
